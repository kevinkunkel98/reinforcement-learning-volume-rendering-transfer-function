# 2026-10-19: task v3 -- the organs in front, not the skin

Follow-up to [task v2](2026-10-17-task-v2.md). Looking at the viewer's actual
renders (policy + search on ts_s0477), the answers that scored 0.9 looked like
small changes. Three things were wrong; none of them in the learner.

## 1. The unlabelled shell covered half the image

At the v2 start, unlabelled voxels -- skin, fat, unsegmented muscle -- take
up about half of the image, and every organ less than 2 % (val, means over
four volumes, `2026-10-19-scripts/shell_probe.py`):

| | other | soft | skeleton | lungs | liver | heart | kidneys | spleen | vessels |
|---|---|---|---|---|---|---|---|---|---|
| v2 start | 0.54 | 0.04 | 0.02 | 0.02 | 0.01 | 0.003 | 0.001 | 0.002 | 0.001 |
| unlabelled row without the soft peak | 0.22 | 0.12 | 0.08 | 0.06 | 0.04 | 0.01 | 0.005 | 0.01 | 0.005 |
| no unlabelled row | 0 | 0.16 | 0.11 | 0.07 | 0.05 | 0.01 | 0.007 | 0.01 | 0.007 |

The shell is the soft-tissue peak lighting unlabelled skin and fat by HU
(`transfer.UNLABELLED_PEAKS`); the policy cannot fade it without fading the
soft-tissue class with it. Because attainment is measured on log visibility,
a "more liver" that is complete on paper moves a fraction of a percent of the
image. The new `visible pp` column (`goals.visible_change`: percentage points
of the image moved toward the goal) puts a number on it -- v2, seed 1, 300
episodes, medians:

| v2 | val att | val pp | test att | test pp |
|---|---|---|---|---|
| policy | 0.54 | 0.72 | 0.51 | 0.68 |
| policy + 30 | 0.72 | 0.82 | 0.70 | 0.79 |
| policy + 200 | 0.89 | 1.05 | 0.91 | 0.95 |
| search 200 | 0.66 | 0.71 | 0.65 | 0.61 |

Relative instructions solved at 0.96 move about 0.5 % of the image.

Rendering the same instructions with the unlabelled row's opacity scaled
(no retraining, `2026-10-19-scripts/shell_render.py`) showed 0.1-0.3 bringing the organs forward while keeping the
body outline; at 0 the organs float. **Task v3** holds it at 0.2
(`transfer.UNLABELLED_OPACITY`, set per task by `goals.use_task_version`; the
browser viewer receives it through `/api/state`).

## 2. Brightness on an invisible organ

Brightening a class that is not visible changes nothing on screen (and its
measured brightness is 0 until it shows). v3 samples brightness only for
classes visible at the start (`sample_instruction(visible_brightness=True)`),
falling back to an absolute instruction like the solvable-only sampler does.

## 3. show_only punished hiding things

"Show only the kidneys" on ts_s0477 (first v3 policy + 200) kept the lungs
bright -- 4.6 % → 8.7 % of the image -- at attainment 0.62; with the lungs
hidden the same answer scored 0.43. The unlabelled tissue sees the lungs
peak, so hiding the lungs also took "other" from 24 % to 3 %, which the keep
term charged as drift, and a fully hidden class overshot its −1 target. v3's
show_only asks every hidden class for the visibility floor and lets the
unlabelled tissue fade (`goals.hide_fully`). Re-scored, the search hides the
lungs and soft tissue completely (0.67). v1 and v2 scoring are unchanged.

## Also fixed: every render was upside down

The TotalSegmentator camera (`azimuth 0, elevation 80`) kept VTK's default
+y view-up, which projects onto inferior: heart and lungs were drawn below the
liver and the patient's left on the viewer's left -- in the offscreen renders
and, by the same camera arithmetic and voxel order, in the vtk.js viewer.
`azimuth 180, elevation 80` gives superior up and the patient's right on the
viewer's left (9c24a65). Visibility uses fixed views, so no number changes.

## Training

The v2 recipe unchanged, with `--task-version v3`
(`2026-10-19-scripts/pipeline_v3.sh`): 3000 + 3 × 1500 starts over train +
train_extra, Dyna rounds with balanced closed-loop fine-tuning, three seeds,
about 3.5 hours on the M1. The first v3 run (before fix 3, `out/rl_mb_v3a`)
tracked v2 round for round (round 1 val 0.36 vs 0.34-0.38, closed loop
0.42-0.43 vs 0.44-0.47).

## Results

Same evaluation as for v2 (`2026-10-19-scripts/eval_v3.py`, `summarize_v3.py`):
vis_eval's fixed 300 episodes per split, median attainment / median visible
pp; policy rows are three seeds, the search from the start is deterministic.
The episodes are drawn per task, so v2 and v3 are compared side by side, not
paired, and attainment means a different thing on the two tasks (show_only
is scored by `hide_fully` on v3).

| | v2 val | **v3 val** | v2 test | **v3 test** |
|---|---|---|---|---|
| start "other" (median share) | 0.49 | 0.27 | 0.49 | 0.25 |
| policy alone | 0.54 / 0.72 | 0.49 / 0.51 / 0.49 (1.5-1.6 pp) | 0.51 / 0.68 | 0.43 / 0.45 / 0.46 (1.4-1.6 pp) |
| policy + 30 | 0.72 / 0.82 | 0.65 / 0.64 / 0.68 (1.8 pp) | 0.70 / 0.79 | 0.67 / 0.64 / 0.65 (1.6 pp) |
| **policy + 200** (viewer) | 0.89 / 1.05 | **0.89 / 0.88 / 0.89 (2.2-2.8 pp)** | 0.91 / 0.95 | **0.89 / 0.87 / 0.88 (2.0 pp)** |
| search 200 from the start | 0.66 / 0.71 | 0.73 / 1.93 | 0.65 / 0.61 | 0.67 / 1.89 |

v2 is seed 1, its best val seed (the other two: policy 0.50, policy + 200
0.89). v3 seeds are listed 0 / 1 / 2.

By kind, v3 val seed 1 (attainment / pp), v2 seed 1 in brackets:

| kind | policy | + 200 | search 200 |
|---|---|---|---|
| relative | 0.45 / 0.70 (0.59 / 0.40) | 0.96 / 1.52 (0.96 / 0.59) | 0.88 / 1.50 |
| compound | 0.44 / 1.55 (0.44 / 0.96) | 0.79 / 2.00 (0.81 / 1.68) | 0.63 / 1.86 |
| show only | 0.44 / 16.7 (0.43 / 4.8) | 0.72 / 20.3 (0.74 / 5.7) | 0.50 / 13.7 |
| absolute | 0.53 / 0.52 (0.62 / 0.51) | 0.98 / 0.94 (0.95 / 0.65) | 0.85 / 0.90 |
| brightness | 0.91 (0.87) | 0.97 (0.92) | 1.00 |

- **The viewer's answer reaches the goal as often and shows twice as much.**
  Policy + 200 stays at 0.88-0.89 val / 0.87-0.89 test while the median
  on-screen change goes from about 1 to 2-2.8 pp; relative instructions move
  1.5 pp instead of 0.6, show_only clears 20 % of the image instead of 6 %.
  The renders agree (`2026-10-19-renders/ts_s0477_v2_vs_v3.png`, start /
  v2 policy + 200 / v3 policy + 200; v3 seed 1).
- **The policy alone got weaker, the search from scratch stronger.** Policy
  alone 0.49-0.51 val against 0.50-0.54 on v2, and 0.43-0.46 test against
  0.49-0.51 -- a small val→test drop v2 did not have. The 200-evaluation
  search from the start rose from 0.66 to 0.73. With the shell faded, a
  local search has less to fight; the policy's lead over it shrinks.
  Policy + 200 still beats it on every seed and split (paired Wilcoxon,
  p < 1e-15), but policy + 30 is now below it on every seed (val 0.64-0.68 vs
  0.73, p ≤ 3e-6; test 0.64-0.67 vs 0.67, p ≤ 6e-4), where on v2 it was
  level (p = 0.04 val, 0.06 test, in the policy's favour).
- Brightness on v3 is only asked of visible classes: 0.90-0.92 for the
  policy alone, against 0.79-0.87 on v2.

The viewer now runs v3 (`server.TASK_VERSION`, default v3) with seed 2, the
best on val (`policy.POLICY_PATH = out/rl_mb_v3/clb_r3_seed2/checkpoint.pt`);
`TASK_VERSION=v2` with the v2 checkpoint restores the previous viewer.
